# 科目一识别类别

在“比赛区域与规划参数”下方展开“科目一识别类别”（默认折叠），选择 0～19 类并勾选目标，然后直接点击“规划并分派”。每次打开页面默认 0 类、全部未勾选；类别不单独保存，也不读取以前保存的类别文件。实际勾选数量与下拉框暂不一致时，按实际勾选发送，不阻断规划、分派或起飞。

| 类别 | 业务编号 |
| --- | --- |
| 车辆1～7 | 0～6 |
| 工事1～4 | 7～10 |
| 人员1～4 | 11～14 |
| 运动的人员1～4 | 15～18 |

编号由赛事任务卡约定，不自动对应检测模型的原始 class_id；检测程序需自行映射。

任务发布端规划时，本次页面选择随任务发给参与分派的无人机；普通地面端只能随自己的任务分派给本机无人机。未连接的无人机只显示规划，仍需操作员连接后重新规划并分派。旧版 `recognition_selection.json` 文件不再读取，可留在本地，不影响流程。

机载端验证任务与校验和成功后，立即发布：

```text
话题：/uavN/competition/recognition_categories
类型：std_msgs/Int32MultiArray
data：[所选类别编号]，按编号升序，无额外计数字段
```

例如选择车辆1、工事1、运动的人员4：`data: [0, 7, 18]`。不选择任何类别时发送 `data: []`。类别数等于数组长度。

采用 `latch=True`：同一机载节点存活时，后启动的订阅者也能收到最后一条选择。机载竞赛程序重启时先发布空列表，不沿用上次任务的类别；新任务接收后再发布本次选择。这是本地 ROS 发布，不向无人机自动重发任务，也不触发起飞。

```bash
rostopic echo /uav1/competition/recognition_categories
```

“任务已确认”表示机载接收任务，不代表检测算法已读取并应用类别。类别话题发布失败会记录警告，但不拒收飞行任务；任务整体校验和、航点及飞行安全参数仍按原逻辑验证。检测程序需订阅上述话题；本次没有修改目标检测或外部程序 B 的代码。其他科目不发布类别选择，旧版无类别字段的科目一任务按 0 类处理。

然后重启竞赛机载程序。UAV2～6 对应地址为 `192.168.1.207`、`.212`、`.217`、`.222`、`.227`。不修改厂家源码，原部署与启动指令不变。
