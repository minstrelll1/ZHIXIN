# 科目一、科目二：固定六机悬停侦察方案

## 比赛时使用

真实比赛区域为既定的 25 个 GNSS/WGS84 点，固定六架无人机。进入科目一或科目二后自动读取本地方案；“显示固定六机方案”复用已加载结果。半径 75 米、速度 5 m/s、每点悬停 10 秒、林缘向林内保留 **5 米**，不限制最小转弯半径。比赛页参数锁定，避免临场误改触发复杂计算。

优化目标为各无人机任务时间之和：`sum(行程 / 5 + 扫描次数 * 10)`。并行完成时间单独列出。本入口仍是规划预览，不取得主控租约，不改写当前任务，不下发真实飞行指令。

## 固定加载与地图保留

`competition_coverage_default.json` 保存默认六机方案、参数、生成时间、方案编号、内容校验和以及源码/比赛边界/地类数据指纹。请求读取并校验已生成结果，进程内按文件版本缓存，返回独立副本。数据缺失、损坏、区域/参数/数量不一致或来源版本变化均返回 HTTP 409，**绝不自动调用求解器**。前端同一页面重复显示直接复用内存方案；遥测更新不重建静态规划画布。

HTML 报告已包含 SVG 航线和本地底图数据。显示时无需下载地图瓦片，也不会自动打开或重载 Google Earth；缩放、拖动、无人机可见性和图层开关按方案编号保存在浏览器本地。清理浏览器存储后回到默认视图。

运行入口 `POST /api/v1/planning/competition-coverage` 默认固定六机，可带 `subject`（科目一/科目二）与 `uav_count`。接口不会接受临场重建开关。后端支持赛前按 1～6 架分别准备方案，**本次随包提供六机方案**；其他数量需赛前准备，不能临场随意改变并期待已有缓存。

只有赛前更新地类、数量或算法时，手动运行一次：

```powershell
.\competition_backend\.venv\Scripts\python.exe .\tools\export_subject12_coverage.py --rebuild --uav-count 6
```

不带 `--rebuild` 仅从已有方案重新导出报告，不进行复杂求解。非默认数量通过 `--output-dir` 导出到单独文件夹；不建议覆盖六机报告。默认方案区域不变、数量六架，故日常启动无需这条预计算命令。

## 算法与数据含义

赛前对多个方向的连通紧凑分区搜索，要求最小外接矩形长宽比不超过 2:1、填充率至少 0.45、单区面积为平均值 0.6～1.4 倍。比较有限候选的真实总机时，无全局最优证明。离散扫描圆贪心覆盖并补齐遗漏，凹口连接采用区域内可视路径，多起点和 2-opt 改善访问顺序。

`waypoints_m` / `scan_waypoints_m` 是悬停点；`waypoint_actions` 包含每点 10 秒。`flight_path_m` 包括凹口导航折点，折点不计为额外扫描；距离按完整路径计算。`waypoints_wgs84` 为 `[纬度, 经度]`，GeoJSON 为 `[经度, 纬度]`。林缘宽度先在完整森林边界计算，然后裁切比赛区域。

不含起降与往返、加减速、遮挡、建筑高度和多机冲突；尚未配置航高。紧凑分区不能替代移动目标去重和跨区接管。`su17_experiment` 不作修改。
