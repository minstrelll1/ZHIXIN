# 成功返航、图片补传与科目一自动上报

## 成功返航标记

定义：本机已到达返航点，并开始下降。收到返航指令、扫描完成、`returning`、`mission_timeout`、普通 `landing` 均不能作为该标记。

**程序 B 的实际状态接口尚待提供，当前不自动推断它已成功返航。** 竞赛端已预留以下接入契约；此契约不表示程序 B 现有版本已实现发布。

程序 B 在上述时刻向 `/uavN/competition/external_status` 发布 `std_msgs/String`，其中 JSON 示例：

```json
{"uav_id":2,"mission_id":"subject1-示例","assignment_checksum":"本次任务中的完整校验码","phase":"return_descent"}
```

任务编号和校验码来自 `/uavN/competition/external_mission`。竞赛端仅接受本机已起飞任务，记录一次后在 `/uavN/competition/successful_return` 发布锁存的 `std_msgs/String` JSON，附带 `event_id`、比赛会话、任务编号、校验码、无人机编号及事件年龄。通过遥测和任务回执传回地面，并同步给发布端。重复消息及无线重连不重复计数。该接口不发送飞行指令，程序 B 继续负责下降。

## 图片缺失清单

每架各自触发，以下条件取先到者，同一图片任务只创建一个最终清单作业：

- 本机成功返航。
- `/uavN/competition/competition_time` 比赛用时达到 23分30秒。

先等待已接受的目标图片完成落盘，再发送缺失清单、补传缺失图片、复核。网络或落盘暂未完成时重试同一作业，完成状态保存在机载 `image_cache/<任务编号>/.final_reconciliation.json`，同任务节点重启不重复创建。

普通图片继续实时回传。断连后的未确认文件通过 `.acked` 确认标记重试，原图和 JSON 不删除；这属于原文件续传，不会额外触发最终缺失清单。旧版本“图片任务开始后19分钟核对”已替换为比赛时间23分30秒。

## 最终结果上报

仅任务发布端执行，手动上报保留。自动上报只选择先满足的一套，选中后不再追加另一套：

| 首先满足的条件 | 自动上报节拍 |
| --- | --- |
| 本次任务六架均成功返航 | 第六架标记后等待3秒，每2秒一次，共10次 |
| 比赛用时达到24分钟 | 每5秒一次，到25分30秒停止；正常连续运行发于24:00～25:25，共18次 |

六机先满足时立即选定返航方案，3秒等待期间即使经过24分钟，也只执行返航方案。无线恢复后用事件年龄判断先后。比赛时间人为回拨不重发已执行过的5秒时段，不集中补发错过的轮次。每次重新汇集最新结果、去重和校验 JSON，再提交并保存回执。等待3秒并不等于最后一架的图片已经全部传完；网络耗时仍影响实际可用结果。

任务分派携带比赛时间。机地连接正常时，通过心跳同步同一比赛会话的计时修订，不覆盖任务航点或重新发送起飞命令；断连时机载按最近快照及单调时钟继续计时。
