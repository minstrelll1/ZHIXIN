# 程序 B 目标回传与赛事整理

实际入口为 `/uavN/target_scheduler/completed_targets`，消息为 `CompletedTargetArray`，内部 `CompletedTarget` 的字段顺序与程序 B 一致。在 `global_id` 后增加 `uint64 detection_count`、`bool tracking_success`。竞赛端的消息包为 `su17_image_transfer`，程序 B 为 `px4_north_camera`；二者线上的字段、顺序与 MD5 必须一致。

首次升级质量/距离字段时，须重新部署并构建竞赛机载端；程序 B 也须使用包含质量字段和 `float32 horizontal_distance_m` 的已编译消息版本。新旧 ROS 消息 MD5 不兼容，不能只更新一端。2026-10-18此次最近完整记录、代表优先级和人员型号补位调整仅涉及地面整理，不增加ROS字段，已支持距离字段的机载端无需再更新。部署及启动命令仍使用 README 原有指令。

`cx/cy` 是相对图片左上角的归一化中心，`w/h` 是归一化宽高。绘框前分别乘实际图片宽、高。框不可用时保留原始 JSON 并回传未标框图片。JSON 记录 `bbox.units=normalized`、`rendered_bbox` 像素框、原始图像时间及选用照片时间。2 秒缓存及超时替代规则不变。

`detection_count` 是累计识别次数，不是动态轨迹点数，也不当作检测概率。`tracking_success` 原样保存：静态精定位完成后成功；动态第 40 个实际上报点才成功，不足 40 点不推定成功。原始 `score` 仍作为 `confidence` 保留。

同机同 ID 以首次反馈的静/动标记锁定：首次静则保持静态，定位按最近距离规则选取；首次动则后续标静的定位点继续进入动轨迹；完整定位历史的有效时长至少10秒且低于3 km/h的时长严格超过70%时，转为静目标并按最近距离规则选取定位。相邻定位时间间隔超过10秒的整段空档不计入有效总时长或低速时长，但前后有效区间仍累计；恰好10秒计入。补传后按定位时间重算，收到得晚不影响原本连续的观测。首次标记及反馈先后采用机载接收顺序，不由磁盘文件名决定。不同无人机同名ID独立整理。

程序 B 的 `category` 使用“人”“车”“建筑物”，判重对应“人员”“车辆”“工事”。静动分开；同大类之间，以及动人员与动车辆之间采用10米阈值，其他组合5米；动目标仍必须满足时间重叠、运动方向和轨迹位置相似条件。同机不同ID也适用这些去重规则。类别大类与型号冲突会写入整理审计，原始字段不改。

静目标重复组按“车辆和工事同级优先 → 识别次数 → 跟踪成功 → 置信度”选代表；人员之间先考虑本次所选型号。动目标优先所选人员型号，然后选择有效点数最多的单机轨迹（最多按40计），长度相同按跟踪成功、次数、分数裁决，取最早40点，不拼接不同飞机的轨迹。定位时间仍使用 `localization_time`，不回退图像时间。

去重后最终最多16个：动目标人员、车辆各最多3个，各自不足的名额转给静目标。静目标最终按“识别次数 → 跟踪成功 → confidence”降序选择和排序；选代表的规则仍如上。优先候选不足时先补其他型号的真实人员去重代表；有效候选至少16个且仍不足时，再从被合并的静目标候选补位，并在 `backfilled` 标明，不拿动目标副本凑数。合格候选不足时可以少于16个，不虚构。原始回传次数和识别次数不作为目标数。完整规则见 [科目一成果上报](subject1_reporting.md#当前去重与数量规则)。

赛事 `targetType/targetModel` 按类别 ID 映射：0～6 为“车辆/车辆1～7”，7～10 为“工事/工事1～4”，11～14 为“人员/人员1～4”，15～18 为“人员/运动的人员1～4”。没有有效编号时兼容 vehicle/building/solider/dsolider 名称及已整理的中文类型。原始 JSON 不改名、不覆盖历史数据。

`float32 horizontal_distance_m`（4字节）是定位时刻无人机与目标的水平距离（米，不包含高度差），新增在 `speed_mps` 之后、`category` 之前。0表示水平位置重合，是有效值；NaN表示不可用。竞赛机载回传保存有限非负值，缺失、负数和非有限值不补成0。静目标（包括动转静）在同任务、同机同ID内取该距离最小且定位坐标/时间有效的完整记录，经纬度、定位时间、图片、类别、型号、识别次数、跟踪状态和置信度均取此记录。相同距离取后收到者；旧记录无距离时兼容原最后记录规则。不同机同名ID不混选。

人员优先本次任务界面所选型号；合格优先目标不足16个时，使用其他型号的真实人员补位并映射到所选同动静人员型号，多选时先补数量较少者。车辆和工事不改成人员。静、动人员最终都用 `targetModel=人员N`；动静类别与坐标/轨迹不因补位改变。详细顺序、未选分组兼容行为及审计见科目一上报说明。

新增质量字段保存在原始 JSON 和本地 `raw-targets.json`、`dedup-decisions.json` 中，赛事 JSON 保持既有字段结构；`confidence` 为原检测分数，不把识别次数伪装成 0～1 的概率。质量排序不保证单帧检测分数递减。


### 定位时间与图片时间

静目标和动目标均以 `localization_time` 表示定位发生时刻。竞赛机载端在回传 JSON 中附加 `localization_clock`，记录该定位时刻与本次开机单调时钟的关系；地面任务发布端只读采样机地时差，在排序和去重前换算为北京时间 ISO 8601（`+08:00`）。原始 JSON、ROS 消息及程序 B 不变。

原 `timestamp/image_stamp` 仍匹配相机图像，图片替代不会改变定位时刻。离线补传使用原来保存的证据。参考暂不可用时新版结果保留原始文件，等待换算，不用接收时间补造；旧版无证据的结果明确记录未校验状态。双方系统时钟均不会被本功能修改，详情见 [科目一上报说明](subject1_reporting.md#目标定位时间与机地时差)。
