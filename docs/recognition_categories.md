# 科目一识别类别

在“比赛区域与规划参数”下方展开“科目一识别类别”（默认折叠），选择 1～15 类，勾选目标，数量一致后点击“保存类别”，再点击“规划并分派”。修改后必须重新保存；保存只影响下一次人工规划，不修改已分派或正在执行的任务。

| 类别 | 业务编号 |
| --- | --- |
| 车辆1～7 | 1～7 |
| 工事1～4 | 8～11 |
| 人员1～4 | 12～15 |

编号由赛事任务卡约定，不自动对应检测模型的原始 class_id；检测程序需自行映射。

类别配置保存在本地后端数据目录的 `recognition_selection.json`。任务发布端规划时，其保存的选择随任务发给参与分派的无人机；普通地面端只能随自己的任务分派给本机无人机。接收端保留任务内的选择，不用本地页面选择覆盖收到的任务。未连接的无人机只显示规划，仍需操作员连接后重新规划并分派。

机载端验证任务与校验和成功后，立即发布：

```text
话题：/uavN/competition/recognition_categories
类型：std_msgs/Int32MultiArray
data：[所选类别编号]，按编号升序，无额外计数字段
```

例如选择车辆1、工事1、人员1：`data: [1, 8, 12]`。类别数等于数组长度。

采用 `latch=True`：同一机载节点存活时，后启动的订阅者也能收到最后一条选择。机载节点重启并恢复已校验的本机任务时，会重新发布该任务的类别。这是本地 ROS 发布，不向无人机自动重发任务，也不触发起飞。

```bash
rostopic echo /uav1/competition/recognition_categories
```

“任务已确认”包含机载接收与本地发布成功，不代表检测算法已读取并应用类别。检测程序需订阅上述话题；本次没有修改目标检测或外部程序 B 的代码。其他科目不发布类别选择，旧版无类别字段的任务仍兼容。

## 更新

更新地面代码并重启地面后端、刷新网页；同时更新竞赛机载端。UAV1 示例，在项目目录执行：

```powershell

```

然后重启竞赛机载程序。UAV2～6 对应地址为 `192.168.1.207`、`.212`、`.217`、`.222`、`.227`。不修改厂家源码，原部署与启动指令不变。
