## 当前六机分区（2026-10-14）

本轮将原 UAV5、UAV6 的完整子区域、航点及执行顺序互换，进返场通道随区域一起交换。UAV1～4 的子区域和航点不变。各机高度仍按机号选择，不随区域交换。

- UAV1 为西中部子区，5 个航点，位于 UAV4 南侧。
- UAV2 为东北部子区，7 个航点，保留原北侧进返场通道。
- UAV3 为东侧、南侧较大区域，36 个航点；包含此前从 UAV4 转交的东侧六点及补充覆盖点。
- UAV4 为北部西侧整块子区，10 个航点，使用西北通道。
- UAV5 接收原 UAV6 子区，10 个航点，使用东侧进入、南侧绕行通道。
- UAV6 接收原 UAV5 西南子区，7 个航点，使用西南通道。

六个子区均为单个连通多边形，无重叠，合并后恰好覆盖全部可侦察区域。原有形状约束、禁飞区及覆盖规则不变。交换按固定参考方案生成，重复生成不会再交换回来。

![四机进返场通道与起降区放大](xuchang_transit_lanes.png)

实际分派仍采用每机本次开机记录的有效GPS作为自己的起降点，重接进返场路线并避让其他已连接飞机的降落点至少2.5米。每架接收机收到全部75个航点到自身降落点的返航路线。高度、降落点归属、一键起飞、返航触发、外部程序B及话题格式均不因本次交换改变。

全部高度档均可选择。“六机不同”高度为UAV1～6对应59、56、53、50、47、44米；“科目二高度”六机均为相对起飞点50米。本表和三维预览使用固定参考起点，实飞进返场使用各机本次开机记录。

## 固定规划文件

- 固定侦察方案：`competition_backend/competition_backend/xuchang_small_prepared.json`
- 固定进返场路线：`competition_backend/competition_backend/external_transit_prepared.json`
- 分区基准：`xuchang_small_partition_reference.json`
- 东侧六点转区基准：`xuchang_small_east_transfer_reference.json`

运行时读取固定方案，分派时按各机起降点重接；起飞后不自动重新规划。离线重新生成命令：

```powershell
python tools/prepare_xuchang_small_plan.py
python tools/prepare_transit_routes.py
python tools/build_plans_3d.py
```

## 开机起降点避让案例

![许昌开机起降点与2.5米避让案例](xuchang_boot_home_example.png)

图中为假设的示例GPS，不是实机数据。以固定参考起点为原点（北、西，米）：UAV1=(10,-6.4286)，UAV2=(0,0)，UAV3=(-10,10)，UAV4=(0,10)，UAV5=(-10,0)，UAV6=(10,10)。UAV1处于UAV2原进场连接直线上，实际规划绕开其降落点。

使用实际运行时函数检查全部6条进场路线及6×75条返航路线：到其他落点最小水平距离不少于2.5米，到外边界及禁飞区至少5米。2.5米是对其他降落点的距离，不代表任意时刻两架飞行中的飞机都有此间距。

[示例规划JSON](xuchang_boot_home_example.json)可导入[三维总览](competition_plans_3d.html)，仅供查看，不用于现场分派。程序B仍使用原有entry_path/return_paths话题。
