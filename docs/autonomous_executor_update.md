# 机载自主执行与任务恢复

规划与分派会发送完整高度和航点。确认起飞后，机载端保存起点、截止时间和电量阈值，到达高度便直接执行航点；最后一个航点完成后直接返航并发出降落指令。地面端不再发送到高度后的 execute_task 或任务完成后的 return_home。人工返航及地面超时/低电量保护仍保留，机载飞行循环也独立检查截止时间和电量。

任务及进度保存在 assigned_task.json 和 assigned_task.json.progress.json。进度在起飞、航点切换、返航及降落阶段原子保存并 fsync；恢复时继续尚未确认完成的航点。相同任务重发不清空进度。

无人机详情顶部“更多”菜单内有“重启机载任务程序”。请求经本机 TCP 或对应 Peer 转发至目标执行器，roslaunch respawn 重新启动该节点，不需要 SSH，也不重启定位或图传程序。为防止主动中断飞行控制，重启按钮请求在机载端仅接受新鲜、未解锁状态。界面“已发送”仅代表请求发出，机载日志显示接受或拒绝结果。

意外程序退出后，同一次 Ubuntu 开机内，任务恢复等待新鲜定位、已解锁、COMMAND_CONTROL 和原生位置控制器就绪，再继续未完成任务。恢复任务不会自动解锁，也不会切换控制模式。若 Ubuntu 已重启，原坐标系可能失效，只恢复任务记录，不自动续飞；需要重新规划。已经完成降落的任务不会自动再次起飞。

更新所有参与测试的地面端代码；更新机载 su17_experiment 后重新编译并重启现有启动命令（包含修改后的 respawn launch）。不要只更新地面端，否则旧机载程序会等 execute_task。

验证顺序：先未解锁测试“更多→重启”，确认恢复任务回执；再用仿真验证起飞后断开地面 TCP，仍能依次执行航点并自主返航；模拟执行器退出，保持定位/飞控运行，验证继续剩余航点、保留原返航点和截止时间。不要以整机重启代替节点恢复测试。
