# “智信—2026”竞赛开发上下文

本文件承接原 Codex 任务“竞赛开发”的关键结论，作为后续开发的共同基线。

## 三个正式科目

1. 环境感知与目标识别：六机在约 1 平方千米区域自主搜索，识别静态/动态目标，回传目标类别、带时间戳图片和经纬度，并处理间歇性通信干扰。
2. 任务指挥与蜂群协作：在科目一基础上增加多机任务分配及面向静态/动态目标的精准投放。
3. 自主导航与障碍穿越：六机携带不同物资进入密林，依靠自主定位、感知、避障和路径规划寻找标识投放点并正确投放。

共同技术底座包括多机身份与通信、任务分配、航线冲突消解、目标检测/定位/跟踪、可靠结果回传、失联策略、投放控制，以及林下建图与避障。

## 当前代码地图

- `src/su17_experiment`：SU17 定制启动、参数和整机集成。
- `src/mission`：现有云台 ArUco 降落与 YOLOv5 跟踪任务。
- `src/Prometheus`：飞控、规划、仿真与通信通用模块（子模块）。
- `src/spirecv-ros`：视觉、云台、检测和 RTSP 链路（子模块）。
- `src/livox_ros_driver2`：MID360 驱动（子模块）。
- `competition_backend`：六机任务指挥台、四边形区域规划、任务分派和地面端服务。
- `src/su17_competition_executor`：每架机载端接收/校验/恢复任务，以及本工程控制或程序 B 适配。

现有通信主链路为：

```text
su17_communication.launch
  -> bridge.launch
     -> communication_bridge
        -> TCP 55555（地面站命令）
        -> TCP 55556（心跳）
        -> UDP 8889（飞行状态）
```

主摄默认地址为 `192.168.1.99`，MID360 为 `192.168.1.100`，机载计算机常用 `192.168.1.88`。多机部署时必须分别规划 IP、Prometheus `robot_id`、ROS `uav_id` 和 PX4 `MAV_SYS_ID`，不能把它们视为同一个编号。

## 推荐模块边界

```text
感知结果
  -> 目标融合与定位
  -> 任务分配
  -> 全局航线规划
  -> 多机冲突消解
  -> 单机局部规划/避障
  -> Prometheus 飞行指令适配
```

算法核心应尽量保持为无 ROS 依赖的库；ROS 节点只负责消息转换、参数、状态机和日志。这样便于单元测试、仿真回放和后续替换算法。

## 四边形规划基线

科目一和科目二均由 `competition_backend` 接收任务区、降落区各四个点。前端可选 `XYZ / ENU` 或 `GPS`；四点按凸四边形边界顺时针或逆时针输入。默认航线间距为 `150m`，最小转弯半径为 `5m`。

规划器搜索扫描方向，在每个方向上将连续覆盖条带与 UAV 做联合动态规划分配。距离包含进入/离开对应降落点的航段和带转弯半径的换线代价。求解优先最小化最长单机航程，并在并列时最小化总航程。GPS 模式以任务区 P1 为 ENU 换算原点；外部程序 B 收到由该规划生成的 WGS84 航线。

XYZ→GPS 只服务于外部程序 B 的 WGS84 接口。所有几何求解先使用局部 ENU 米制坐标；本工程自主控制输入 XYZ 时不做转换。GPS 输入则先投影到 ENU 计算，再按需要转换回 WGS84。

## 已知注意事项

- 根目录原有脚本名为 `complie*.sh`，为兼容现有部署暂不改名。
- 地面站连接、多机网络和图数传链路应在算法联调前单独完成验证。
- 现有系统没有完整的“检测到目标后可靠发送 JPEG 到地面端”闭环，后续需设计独立接口。
- 竞赛文件中的时限、干扰参数、投放判定半径和赛事数据接口仍需以最终规则为准。
