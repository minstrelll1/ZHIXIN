# 地面程序诊断日志

每次启动自动创建 `ground_logs/sessions/日期_时间_随机编号/events.jsonl`，UTF-8 编码，每行一条 JSON。记录实时写入并刷新，不需要点击保存，也不需要等程序关闭。

- 入口：终端编号、机型、发布角色、配置同步结果、服务启动失败。
- 操作：请求开始与结束、接口、请求编号、参数摘要、HTTP 状态、错误和耗时。
- 规划分派：作业编号、排队/替换、每阶段耗时、任务编号、任务内容摘要、每机发送与回执、校验值。
- 每机发送前另存完整 `task_uavN_编号.json`，包含航点、降落点、坐标基准、高度、控制模式、识别类别等实际下发参数；副本只供排查，不用于自动恢复任务。生成副本不代表发送成功，须结合后续事件和机载回执。
- 飞行：预检结果、起飞指令、到达任务高度、执行阶段、返航和落地事件；关键遥测状态变化。
- 回传：图片链路连接/断开、认证失败、任务计时、图片保存路径与字节数、清单缺失数量、跨终端同步结果。
- 赛事上报：整理文件的 SHA-256、目标数量、发送开始、HTTP 状态、赛事回执及其文件位置。HTTP 成功不等同于赛事已受理，仍以赛事回执为准。
- 程序管理：SSH 或机载程序管理失败，程序运行状态变化。

正常退出会写入“程序会话正常结束”。强制结束进程、系统崩溃或断电时可能没有结束标记；已经刷新的日志通常保留，但不能保证断电前操作系统缓存中的最后部分已经写入物理磁盘。关闭浏览器页面不等于关闭地面后端。

每个会话文件达到约 20 MB 时轮转，保留当前文件和最多四份旧分卷；早期内容超过该容量会被覆盖。旧会话目录不自动删除。排查时复制整个对应会话目录；如需程序原始打印，再附上 `ground_logs/programs/` 和 `ground_logs/mediamtx.log`。任务历史仍在 `competition_backend/data/events.jsonl`，赛事完整回执仍在 `received_images/subject1_reports/`。

不记录密码、认证令牌、请求头、图片/点云二进制及完整上报文档。长列表和长文本会截断，诊断日志不能替代 rosbag、CSV、原始图片或任务文件。高频网页查询不逐条记录。未到达后端的浏览器请求无法记录。

日志目录可用环境变量 `COMPETITION_DIAGNOSTICS_DIR` 指定。更新只涉及地面程序，无需部署机载代码；地面启动命令不变。
